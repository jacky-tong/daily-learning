# 2026-10-06｜从相对位置算出一次追踪修正

## 今天学什么

单个无人机已知自己和目标的二维位置时，怎样算出目标有多远、在哪个方向，并朝“与目标保持 3 m”这个要求修正一步？这处在“目标位置 → 相对位置 → 追踪控制 → 无人机位置更新”这段链条中。

## 本地代码与输入

当天在 VS Code 运行并理解的脚本：`~/Desktop/everyday/day1.py`。本记录依据该脚本和运行输出；仓库中没有另建重复脚本。

运行命令：`python3 ~/Desktop/everyday/day1.py`

| 量 | 数值 | 含义 |
| --- | --- | --- |
| 无人机初始位置 | `(2.0, 1.0)` m | 当前所在位置 |
| 目标位置 | `(8.0, 5.0)` m | 目标所在位置 |
| `desired_distance` | `3.0` m | 想保持的间距 |
| `gain` | `0.2` | 本次修正距离误差的比例 |

## 核心理解

1. 相对位置是 `dx = 8 - 2 = 6` m、`dy = 5 - 1 = 4` m。
2. `distance = hypot(dx, dy) = √(6² + 4²) ≈ 7.21` m，表示当前实际距离。它与 `discrete`（离散）不是同一个词。
3. `atan2(dy, dx) = atan2(4, 6) ≈ 33.69°`，表示从无人机指向目标的方向，相对水平向右的方向逆时针测量。`atan2` 同时利用 `dx`、`dy` 的符号判断象限。
4. `error = distance - desired_distance ≈ 4.21` m，说明目前比期望间距远约 4.21 m。`gain × error ≈ 0.84` m 是这一步沿目标方向移动的距离；`dx / distance` 和 `dy / distance` 把这段移动分配到横向和纵向。
5. “离散更新”指按一次、两次这样的步骤更新位置。本脚本只计算并执行**一次**更新，没有循环；要连续追踪，需要在每一步重新计算相对位置与控制量。

## 亲手验证

### 实际运行输出

```text
初始距离: 7.21 m
目标方位: 33.69°
距离误差: 4.21 m
移动后无人机位置: (2.70, 1.47)
移动后距离: 6.37 m
```

新距离仍大于目标间距 3 m，但距离误差由约 4.21 m 减为约 3.37 m，符合“向目标靠近，同时逐步趋向期望间距”的预期。

## gain 的现象

在相同初始位置、目标位置和期望间距下，按脚本的**同一公式补充核算**（不是上面那次 VS Code 运行的额外输出）：

| `gain` | 本步沿目标方向移动 | 更新后距离 |
| ---: | ---: | ---: |
| 0.1 | 0.42 m | 6.79 m |
| 0.2 | 0.84 m | 6.37 m |
| 0.5 | 2.11 m | 5.11 m |
| 1.0 | 4.21 m | 3.00 m |

在这个目标静止、只更新一次的简化模型里，`gain` 越小，每步修正越慢；`gain` 越大，每步修正越多。`gain = 1` 恰好消除这一次距离误差；大于 1 则可能越过期望间距。真实无人机还受运动约束和观测变化影响，不能仅凭这张表选控制参数。

## 自测

1. `distance` 与 `desired_distance` 分别是什么？前者是当前实际距离，后者是希望保持的距离。
2. 为什么 `gain = 0.2` 后的距离仍大于 3 m？因为这一步只修正距离误差的 20%。

## 资料

- [Python 官方文档：`math.hypot` 与 `math.atan2`](https://docs.python.org/3/library/math.html)：分别用于计算二维距离与方向角。

## 一句话复盘

先用相对位置算距离和方向，再用 `gain × 距离误差` 决定这一步沿目标方向移动多少，就能把“目标在哪”转成一次可验证的追踪修正。
