# Daily Learning

每天用约 15 分钟，动手完成一个与**单个无人机追踪目标**有关的小实验，并留下可以运行、可以复习、可以验证的成果。

这个仓库有两个目标：

1. 沿着单机目标跟踪主线持续学习，而不是每天随机换题；
2. 用真实的笔记、代码和实验结果维持稳定的 GitHub 贡献记录。

## 内容优先级

1. 单个无人机追踪目标：目标状态估计、视觉跟踪、跟踪控制、视野保持、遮挡处理、追踪轨迹生成；
2. 服务于目标跟踪的轨迹规划：预测、拦截、动态约束、避障和重规划；
3. 其他无人机知识：仅在当天没有合适的前两类主题时使用。

## 每日 15 分钟流程

每天 20:30 会收到提醒。对 Codex 说：`开始今日 GitHub`。

随后会完成：

1. **0～2 分钟：**看懂今天只解决哪一个跟踪问题；
2. **2～5 分钟：**理解一个核心概念和一张数据流图；
3. **5～12 分钟：**运行或修改一个最小实验；
4. **12～14 分钟：**观察结果，并亲手改变一个参数；
5. **14～15 分钟：**回答自测题并提交学习成果。

Codex 会准备材料、运行自动检查并提交通过检查的内容；你负责亲手执行关键一步、观察现象并说明结果。

## 仓库结构

```text
daily/       每日学习笔记
labs/        与笔记配套的最小实验
scripts/     内容与代码校验
templates/   15 分钟每日笔记模板
```

## 起点

- 第一天先用 [Git 的 blob、tree 与 commit](daily/2026/10/2026-10-04-git-object-model.md) 建立版本管理基础；
- 后续内容按照 [单机目标跟踪学习路线](ROADMAP.md) 推进。

## 原则

- 不创建空提交，不复制无来源内容；
- 每天只解决一个小问题，实验应能在约 7 分钟内完成；
- 每次实验都必须有输入、输出、预期现象和成功判据；
- 不为追求绿格子向外部项目发送低质量 Issue 或 PR；
- 自动化负责减少重复劳动，学习和判断仍由人完成。
