# Daily Learning

每天用约 15 分钟，动手完成一个与**单个无人机追踪目标**有关的小实验，并留下可以运行、可以复习、可以验证的成果。

这个仓库有两个目标：

1. 沿着单机目标跟踪主线持续学习，而不是每天随机换题；
2. 用真实的笔记、代码和实验结果维持稳定的 GitHub 贡献记录。

## 内容优先级

1. 单个无人机追踪目标：目标状态估计、视觉跟踪、跟踪控制、视野保持、遮挡处理、追踪轨迹生成；
2. 服务于目标跟踪的轨迹规划：预测、拦截、动态约束、避障和重规划；
3. 其他无人机知识：仅在当天没有合适的前两类主题时使用。

## 每日 15 分钟流程

每天 20:30，定时任务会先查看学习进度、检查可用环境、检索第一手资料，然后直接发送当天完整学习包。学习包已经包含：

- 今日唯一目标，以及它在单机目标跟踪链条中的作用；
- 直觉讲解和必要的最少量公式；
- 可以亲手完成的最小实验；
- 需要修改的一个参数；
- 预期现象、成功判据、自测题和来源；
- 当天应使用 Linux 还是 Mac 的明确结论。

你不需要再输入“开始今日 GitHub”。收到学习包后只需决定是否现在学习；回答愿意后，会直接进入已经准备好的实验。

时间固定分配为：

1. **0～2 分钟：**看懂今天只解决哪一个跟踪问题；
2. **2～5 分钟：**理解一个核心概念和一张数据流图；
3. **5～12 分钟：**运行或修改一个最小实验；
4. **12～14 分钟：**观察结果，并亲手改变一个参数；
5. **14～15 分钟：**回答自测题并提交学习成果。

定时任务负责选题、环境判断、检索和备课；你负责亲手执行关键一步、观察现象并说明结果。只有你确认学习并完成实操后，才会更新 GitHub。

## 运行环境选择

每天只进行一次短时、只读的 Y9000P 检查：

- 如果 SSH 可达并明确返回 Linux，当天优先准备 Linux 轻量实验；
- 如果关机、连接超时、处于 Windows、Linux SSH 未启动或系统类型无法确认，立即使用 Mac；
- 检查只读取系统类型、主机名和当前用户，不创建文件、不启动程序、不唤醒或重启电脑；
- 定时任务不反复重试。确认学习后，真正运行实验前再检查一次；若此时离线则回退到 Mac；
- Mac 方案优先使用 Python 标准库或已有轻量环境，不默认要求 ROS、GPU、Docker、大型数据集或完整项目克隆；
- 远程机不可用不会阻塞当天学习，也不会阻塞 GitHub 贡献。


## 起点

- 第一天先用 [Git 的 blob、tree 与 commit](daily/2026/10/2026-10-04-git-object-model.md) 建立版本管理基础；
- 后续内容按照 [单机目标跟踪学习路线](ROADMAP.md) 推进。

## 原则

- 不创建空提交，不复制无来源内容；
- 每天只解决一个小问题，实验应能在约 7 分钟内完成；
- 每次实验都必须有输入、输出、预期现象和成功判据；
- 不为追求绿格子向外部项目发送低质量 Issue 或 PR；
- 自动化负责减少重复劳动，学习和判断仍由人完成。
